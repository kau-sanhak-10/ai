## 1. 결론

**기본 API는 Gemini (`gemini-3.5-flash-lite`)로 선정**한다. 사용자 실행 결과에서 문자 호출, 사진+문자 호출, JSON/Pydantic 구조화 출력, 요청별 토큰 기록이 확인되었다. 현재 코드의 사진 샘플 `boiler_40.png`에서 추출한 모델명 `NGB 554`가 원본과 일치함을 사용자가 확인했다. 이는 해당 샘플의 모델명 대조 결과이며 전체 이미지 판독 정확도 평가를 뜻하지 않는다.

**대체 후보는 OpenAI GPT (`gpt-4.1-mini`)로 조건부 선정**한다. OpenAI SDK 호출 시 HTTP 429, `credit_balance_exhausted`가 확인되어 실제 GPT 성공 응답, 이미지 인식, 구조화 출력은 *미검증*이다. 대체 후보의 인터페이스를 구현하고 비용 없는 모의 테스트를 수행했지만, 운영 중 자동 전환 가능한 백업으로 간주해서는 안 된다. **GPT의 정상 호출·한도·실제 사용량 검증은 후속 작업으로 보류하고, 현재 기본 구현은 Gemini로 진행한다.**

## 4. 보안 및 운영 주의점

- API 키는 서버/로컬 Python 실행 환경에서만 주입. 프론트엔드·Git·로그에 포함 금지. 현재 구현은 키 주입 경로만 제공하며 운영 배포의 Secret 권한 설정은 아직 검증되지 않았다.
- 현재 폴더는 Git 저장소이며 로컬 `git ls-files .env` 결과는 비어 있다. 원격 전체 이력의 비밀키 유출 여부까지 검사한 것은 아니다.
- `.gitignore`가 존재해도 이미 커밋된 키는 보호하지 못하므로 저장소 연결 시 별도 점검 필요.
- 사용자 코드 검사 정규식에서 하드코딩 의심 표현이 검색되지 않았으나 전체 비밀 검색을 보장하지는 않는다.
- OpenAI 429는 크레딧 부족과 속도 제한을 구분한다. Gemini 429는 원인이 불명확하면 `rate_or_quota`로 분류한다. 두 SDK 모두 자동 재시도를 끈다. 정확한 제공사 한도는 계정 콘솔에서 확인한다.
- 이미지 인식값은 최종 고장 진단 근거로 사용하지 않고 필요시 사람에게 확인 요청.
- Gemini 로그는 기존 CSV이다. OpenAI 요청 로그는 SQLite를 사용한다. 공급사 전체 청구량과 앱 로그 토큰 합계는 다를 수 있다.

## 7. 실행 및 완료 확인 절차

저장소 루트에서 실행한다. LLM 호출 경로에서는 로컬 CLI가 `.env`의 키를 읽으며 두 LLM 서버 진입점은 환경변수만 읽는다.
모델 변경은 프로세스 환경변수 `GEMINI_MODEL`, `OPENAI_MODEL`로 지정한다.
call 명령은 외부 API 사용량과 비용을 발생시킬 수 있다.

```powershell
uv sync --locked
uv run pytest
uv run ruff check
uv run ruff format --check
# .env가 없다면 복사한 뒤 사용하는 제공사의 키를 직접 입력한다.
# Copy-Item .env.example .env
uv run python -m app.llm.cli --provider gemini --message "난방이 안 돼요"
uv run python -m app.llm.cli --provider gemini --message "사진의 표시 확인" --image samples/boiler.png
uv run python -m app.llm.cli --provider openai --message "난방이 안 돼요"
uv run python -m app.llm.cli --provider gemini --mode usage
uv run python -m app.llm.cli --provider openai --mode usage
uv run python -m app.llm.cli --mode errors
```

`samples/boiler.png`는 예시 경로다. 비식별 JPG/PNG를 별도 준비한다. CLI는 기본적으로 요청 ID·모델·사용량만 출력한다. 구조화 추출 결과를 보려면
호출 명령에 `--show-result`를 추가한다. 결과는 터미널에만 출력하며 사용량 로그에는 저장하지 않는다.
실패 시 상세 예외 원문을 출력하지 않는다.
서버에서 추출 결과는 `analyze_gemini(message, image_path)`의 반환값으로 확인한다.

- Gemini: `results/gemini_multimodal_calls.csv`, OpenAI: `results/openai_calls.sqlite3`.
  `results/`는 Git에서 제외한다. Gemini CSV의 기존 열 구조는 유지한다.
- Gemini JSON 검증 실패·빈 출력도 응답에 포함된 입력/출력/총 토큰을 보존한다.
  제공사가 사용량을 반환하지 않은 실패는 빈 값이며 0토큰 청구를 뜻하지 않는다.
- Gemini SDK 오류는 `code`에서 HTTP 상태 코드를 기록한다. 오류 정책은
  `classify_error()`로 확인할 수 있으며 정책 함수 자체는 재시도를 실행하지 않는다.
- Gemini `HttpRetryOptions(attempts=1)`, OpenAI `max_retries=0`으로 자동 재시도를 끈다.
  429는 반복 호출하지 말고 콘솔에서 속도/일일/결제 한도를 확인한다.
- 로그 저장 실패는 예외로 전달한다. 운영에서는 쓰기 가능한 영속 저장소·접근권한·보존기간을
  설정해야 한다. Gemini CSV는 단일 프로세스 검증용이며 다중 워커에서는 동시 쓰기가 가능한
  저장소로 이관해야 한다. 원문 메시지·사진·키·상세 오류 문구는 로그에 저장하지 않는다.

### 실제 계정 한도 확인 기록

코드는 계정 콘솔 한도를 자동 조회하거나 RPM/TPM을 강제 제한하지 않는다.
오류 처리 구현과 실제 한도 확인은 별개다. 의도적으로 429를 유도하지 말고 계정 콘솔에서
다음 항목을 확인하고 비밀키·계정 식별자를 가린 자료 또는 확인 기록을 남긴다.

| 제공사 | 확인 상태 | 모델 | RPM / TPM / RPD | 결제·비용 한도 |
|---|---|---|---|---|
| Gemini | 2026-10-23 사용자 제공 AI Studio 화면 확인; 프로젝트 별칭 미기록 | gemini-3.5-flash-lite | 15 / 250,000 / 500 | 현재 화면에는 없음, 미확인 (과거 Free 보고와 구분) |
| OpenAI | 미확인 | gpt-4.1-mini | 미확인 | 크레딧 부족 보고, 재확인 필요 |

Gemini RPM/TPM/RPD는 사용자 제공 화면으로 확인했다. 사용한 키와 콘솔 프로젝트의 일치,
프로젝트 별칭·결제/비용 한도와 OpenAI 한도는 추가 확인하여 본 문서에 기록한다. 운영 Secret 주입 검증도 배포 환경에서 별도로 수행한다.
API 접근 검증은 본 작업에서만 관리하고 IF-02는 결과를 참조한다.
Jev 접근·비교 과제는 DS-05, 선택형 판단 비교는 AI-07에서 관리한다.

> 이전 사용자 실행 수치는 전달된 결과의 요약이다. 원본 CSV·사진·계정 화면은
> 저장소에 포함되어 있지 않으며 이번 보완에서 실호출하지 않았다.


### 구조화 결과 확인

```powershell
uv run python -m app.llm.cli --provider gemini --message "경동나비엔 보일러인데 난방이 안 돼요" --show-result
uv run python -m app.llm.cli --provider gemini --message "사진의 표시 확인" --image "samples/boiler_40.png" --show-result
```

`extraction`에 제조사·모델명·오류코드·근거 등이 표시된다. Gemini는 `missing_fields`,
`needs_review`도 출력한다. 사진 속 글자와 `extraction`을 직접 대조한다.
이전 호출의 추출값은 저장하지 않으므로 복원할 수 없다. 위 명령은 새 API 요청을 발생시킨다.
